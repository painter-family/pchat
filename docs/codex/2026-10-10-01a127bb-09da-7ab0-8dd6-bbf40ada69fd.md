Use **Cloudflare Worker secrets** for production credentials. Keep `.env.local` for local development—it is already ignored by Git.

For this app, configure:

| Setting | Cloudflare storage |
|---|---|
| `AUTH_GOOGLE_SECRET` | Secret: Google OAuth client secret |
| `AUTH_SECRET` | Secret: a new, random production session secret |
| `AUTH_GOOGLE_ID` | Environment variable: Google OAuth client ID |
| `AUTH_URL` | Environment variable: `https://your-domain.com` |

You don’t manually configure a Google access token for sign-in. Auth.js handles the OAuth exchange using the client ID and client secret.

In Cloudflare, select **Workers & Pages → your Worker → Settings → Variables and Secrets**. Add the sensitive values using the **Secret** type. Keep secrets out of Git, Wrangler’s plaintext `vars`, and `NEXT_PUBLIC_*` variables. [Cloudflare secret management](https://developers.cloudflare.com/workers/configuration/secrets/).

Once Wrangler is configured for the Worker, you can also enter secrets interactively:

```bash
npx wrangler secret put AUTH_GOOGLE_SECRET
npx wrangler secret put AUTH_SECRET
```

In Google Cloud Console, register this exact authorized redirect URI:

```text
https://your-domain.com/api/auth/callback/google
```

It must match the deployed domain and callback path exactly. [Google OAuth setup](https://developers.google.com/identity/protocols/oauth2/web-server).

**The app also needs storage changes before deployment to Workers.** It currently stores SQLite and uploads on local disk; Workers’ writable filesystem is temporary. I recommend migrating chat records to **Cloudflare D1** and images/videos to a **private R2 bucket**, preserving the existing membership checks when serving media. [Workers filesystem](https://developers.cloudflare.com/workers/runtime-apis/nodejs/fs/), [D1](https://developers.cloudflare.com/d1/), [R2](https://developers.cloudflare.com/r2/).
